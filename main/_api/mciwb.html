mciwb#

Minecraft Interactive World Builder: build in a Minecraft world from Python.

The main entry point is Iwb, which connects to a Minecraft server. The building blocks (Vec3, Item, Direction, Volume, polygon etc.) come from the mcwb library. These and the classes below can all be imported from mciwb.imports. mciwb.builders has higher level building blocks: roofs, arches, stairways, foundations and schematic files.

Read and draw regions with scan and render from the mciwb.render module (or mciwb.imports). They are not imported here, where a function called render would hide the mciwb.render module.

Submodules

render

Render a region of a Minecraft world to an image, so that you (or an AI agent) can see what a build looks like without joining the game.

builders

Higher level building blocks: roofs, arches, columns, stairways, roads, foundations that follow the terrain, and Sponge schematic files.

class mciwb.Iwb(server: str = 'localhost', port: int = 20100, passwd: str = 'default_pass')[source]#

Interactive World Builder class. Provides a very simple interface for interactive functions for use in an IPython shell, or in scripts.

Connect to the server started by mciwb start with:

world = Iwb()

Call stop when finished to stop any background monitoring threads.

Variables:

  • player – The default Player object.

  • copier – CopyPaste object for the above player.

  • signs – The Signs object for the above player.

  • world_folder – The server’s world folder, if it is on this machine. scan and render read blocks from its files, which is much faster than over RCON. Set for the server of mciwb start when it uses the default --folder: for another folder, set it yourself, e.g. world.world_folder = Path("/my/server/world").

Initialise the world object.

Parameters:

  • server – the server address, defaults to the local server started by mciwb start

  • port – the server’s RCON port

  • passwd – the server’s RCON password

Raises:

SessionTimeout – if the connection to the server fails

save(filename: str | Path, vol: Volume | None = None)[source]#

Save a Volume of blocks to a file. The volume can be specified in the vol parameter or alternatively defaults to the current copy buffer.

The file is saved in the mcwb format which is a JSON file containing a 3d array of Item objects. If the filename ends in .schem it is saved as a Sponge schematic instead, with the block states of stairs, slabs and logs (see mciwb.builders.Schematic.from_world), which other Minecraft tools such as WorldEdit can load.

The file can be loaded into a world using the load method.

Parameters:

  • filename – the name of the file to save to

  • vol – the volume to save

Raises:

ValueError – if no vol is given and there is no copy buffer

The blocks are loaded from a file in the mcwb format which is a JSON file containing a 3d array of Item objects, or from a Sponge schematic if the filename ends in .schem (see mciwb.builders.Schematic).

Parameters:

class mciwb.Signs(player: Player)[source]#

Monitor the world for signs placed by a player. Perform an action based on the text of the sign.

Each sign object can be used to monitor the placing of signs by a single player. The object can be hooked to functions that are to be called when a sign is placed by the player.

By default each Sign object is initialized with select/copy/paste functions. Additional signs with callback functions can be added.

For best results, use the bound methods of an object for the callback functions. That way the user code can manage state within the object providing those functions.

class mciwb.Wall(height: int | None = None, item: Item | str = Item.STONE, profile: list[Any] | None = None)[source]#

Draw walls between pairs of points in the world.

A wall is drawn column by column along the line from its start to its end. The profile describes the columns, and is repeated along the length of the wall:

  • the profile is a list of columns

  • each column is a list of blocks, from the top of the column down

  • each block is an Item, or a list of Items to make the wall more than one block thick (extending to the right of the direction of drawing)

If the column is shorter than height it is repeated to fill the height.

For example, a castle wall with crenellations on top:

battlement = [Item.AIR, Item.STONE_BRICKS, Item.STONE_BRICKS]
solid = [Item.STONE_BRICKS] * 3
wall = Wall(profile=[solid, battlement])
wall.set_start(Vec3(0, -60, 0))
wall.draw(Vec3(20, -60, 0))
Parameters:

  • height – the height of the wall, defaults to the length of each column in the profile

  • item – the block to build a plain wall from, used when no profile is given

  • profile – the profile of the wall, a list of columns

set_start(pos: Vec3)[source]#

Set the start point of the next wall. The wall is built on top of the block at pos.

class mciwb.Client(*args, frag_threshold: int = 4096, **kwargs)[source]#

An RCON client for Minecraft Java Edition that is safe to use alongside the clients of other threads in this process.

Each command waits for any command running on another connection to complete, so that the server returns the output of this command only.

Set an optional fragmentation threshold and command in order to detect fragmented packets.

For details see: https://wiki.vg/RCON#Fragmentation

mciwb.parse_nbt(s_nbt_text: str) → object[source]#

Naive deserialization of an SNBT string into a object graph of Python types.

Note that this is one way only since the following details are lost: - distinction between byte, short, int long, types (suffixes of b,s,none,l) - distinction between float, double types (suffixes of f,d) - distinction between SNBT and raw JSON (enclosed in single quotes)

See https://minecraft.wiki/w/NBT_format
